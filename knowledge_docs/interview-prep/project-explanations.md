# Project Explanations

A strong project explanation shows technical understanding, ownership, and the
ability to connect engineering work to a real problem.

## Short structure

Begin with the user or business problem. Name the main technologies only after the
purpose is clear. Explain what you personally built and the result.

## Architecture

Describe the request or data flow from input to output. Mention the frontend,
backend, database, external services, and deployment only when they are relevant.

## Decisions and trade-offs

Choose one or two meaningful decisions. Explain the alternatives, why you selected
the final approach, the limitation you accepted, and how you verified it.

## AI-assisted development

When AI helped, identify the task it assisted with, what you accepted or rejected,
and how you tested or reviewed the result. Do not describe generated code as work you
cannot explain.

## Follow-up readiness

Prepare for questions about failures, security, testing, scale, performance, and what
you would change with more time.
